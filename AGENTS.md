# Oney — the talking bunny (agent guide)

**This file is the single source of truth for this repo.** `CLAUDE.md` and `README.md` just point here. When you change how something works, update this file in the same commit.

A private web app built by Adam for his wife. She opens it on her phone, taps **Call**, and her real plush bunny, **Oney**, picks up as a 3D bunny on a FaceTime-style call. Oney talks back in a little girl's voice, moves (waves, nuzzles, gets sad, hops), and remembers things between calls.

- Live: **https://miffy-mu.vercel.app** (passcode-locked; ask Adam for the passcode)
- Repo: `adamlewison/miffy`. **Pushing to `main` auto-deploys to Vercel.**
- Reference photos of the real toy: `reference/photos/`. Adam's original plan: `reference/original-build-plan.md`.

## 1. The non-negotiables

### She is a 3–4 year old little girl
Every change to voice, prompt or personality must keep this true:
- **Name:** written "Oney" but said **"WUN-ee"**, like the number one (her sister is **Two-y**). The family also calls her **Miffy**. The prompt always spells it `spokenName` ("One-y"), because the voice model pronounces what it reads, and "Oney" comes out as "own-ee". To check: `tools/voice-test.mts --transcribe` should hear her name as "Wunny".
- **Family:** she calls the user **Mommy**, Adam **Daddy**, and Mommy's mum **Booba**.
- **Voice:** a small child's: high, squeaky, bubbly. The realtime voices are all adults, so we use `sage` on `gpt-realtime-2.1` plus a client-side pitch shift (`pitchSemitones`, default +8, `public/pitch-shifter.worklet.js`).
- **Pronunciation:** toddler sounds (da/den/dat, w for r/l, "pasketti", "nana", "free" for three). One or two baby-words per sentence, always understandable.
- **Grammar:** "I runned", "me so happy", "bestest", and she calls herself "One-y".
- **Sentence structure:** tiny sentences, "and... and... and den", repetition, sudden topic jumps, "why?" questions. **Never** grown-up phrases ("good evening", "that sounds lovely", "let me think").
- **Body language:** wave (paw beside her face), nuzzle/cuddle, sad (head sags, paws to her face), plus hops. These go through the `express` tool and are **never narrated** ("I'm waving" is a bug).

If any line in a test transcript sounds like a grown-up, it's a bug.

### She looks like the real toy
`public/bunny.glb` is **generated** by `blender/build_oney.py`. Edit the script and rebuild; never hand-edit the GLB. Compare against `reference/photos/`. She must stay recognisably the real toy:
- one continuous stuffed body: head, arms and legs blended at the seams, never stuck-on parts
- tan terry fur; cream muzzle, tummy, soles, paw undersides and tail
- a big mustard triangle nose and black embroidered eyes
- long lop ears with beige linings
- flat mitten paws with finger stitches

### She is solid
Arms and ears never pass through her head, body, legs or each other. This is enforced every frame by `src/components/bunny/collide.ts`, using `public/bunny.collision.json`, which is regenerated by the build. `npm run check:solid` must pass before shipping any model or pose change.

## 2. How it works (the simple version)

1. **Her body is code.** `blender/build_oney.py` runs Blender headless (as a Python library) and builds her from maths: each part is a smooth 3D shape sized from the photos, the parts are blended into one stuffed surface, and patches and stitches are laid on top. It also bakes soft shadows, adds a 21-bone skeleton, and exports `public/bunny.glb` plus `public/bunny.collision.json`.
2. **Her fur is drawn live** (per-strand warm/cool colour, soft tufts of clumped length, sun-bleached tips and a warm scattered-light glow in shadow). `fur.ts` redraws each fabric part 10 times on phones and 20 on desktop, each layer pushed slightly further out and cut into strands, so she looks fluffy. The GLB itself is smooth.
3. **Her movement is code.** `rig.ts` turns her bones every frame: breathing, springy ears, a head bob from her voice volume, and gesture poses. `collide.ts` then nudges any arm or ear out of her body.
4. **Her voice is OpenAI Realtime.** Audio goes straight from the phone to OpenAI over WebRTC. Our server only mints a 10-minute key and builds her instructions (character sheet plus memories). Her reply audio is pitch-shifted on the phone and drives the talking animation.

```
phone ──WebRTC audio──▶ OpenAI Realtime            (audio never touches our server)
  ├─ /api/session  ──▶ mints a 10-min client secret + builds her instructions + memories
  └─ /api/memories ◀── transcript after the call → small model → 3–5 facts → Turso
```

## 3. Setup

### Web app
- Node 22+, then `npm install`.
- `cp .env.example .env.local` and set at least `OPENAI_API_KEY`.
- `npm run dev` → http://localhost:3000. The mic needs HTTPS on a phone: use `npx next dev --experimental-https` or a Vercel preview.

Environment variables (see `.env.example`):

| Var | Purpose |
| --- | --- |
| `OPENAI_API_KEY` | server only. Mints realtime keys, extracts memories, voice samples |
| `BUNNY_PASSCODE`, `AUTH_SECRET` | passcode lock. Unset = no lock (dev only) |
| `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | memory store. Unset = in-RAM (lost on restart). `file:local.db` works locally |
| `AI_GATEWAY_API_KEY` | server only. Vercel AI Gateway key, used by `/api/live-token` for the Gemini Live test page |
| `BUNNY_VOICE` (`sage`), `BUNNY_PITCH` (`8`) | voice and pitch overrides |
| `REALTIME_MODEL` (`gpt-realtime-2.1`), `MEMORY_MODEL` (`gpt-5.4-mini`) | models |
| `NEXT_PUBLIC_MAX_CALL_MINUTES` (`20`) | hard call cap |

### 3D model toolchain (Blender as a Python module)
`bpy` wheels are tied to one Python version: **bpy 5.3 needs Python 3.13**.
```bash
python3.13 -m venv .bvenv
.bvenv/bin/pip install -r blender/requirements.txt     # bpy, scikit-image, numpy (~400 MB)
npm run model            # = .bvenv/bin/python blender/build_oney.py --out public/bunny.glb   (~3-4 min)
npm run model:renders    # same, plus Cycles preview renders in .oney-out/renders/
```
- There's no GPU in cloud sandboxes, so **EEVEE crashes** (no EGL). The script uses **Cycles on CPU** for the AO bake and previews.
- The pip `bpy` has no Draco library, so the GLB is exported uncompressed (about 2.7 MB, fine).
- **The build is deterministic.** Rebuilding without changes produces a byte-identical `bunny.glb`, so any diff is a real change.

### Test tools
- **Playwright + Chromium:** `tools/shots.cjs` and `tools/solid.cjs` need `require('playwright')`. Claude cloud sandboxes have it preinstalled. Elsewhere: `npm i -D playwright && npx playwright install chromium`.
- **Pillow:** `tools/sheet.py` needs Pillow, and `tools/audio/f0.py` needs numpy (`pip install pillow numpy`, system Python is fine).
- **Server:** the tools talk to a running app (`ONEY_URL`, default `http://localhost:3000`). If it has a passcode, set `BUNNY_PASSCODE`. You can also point `ONEY_URL` at the live site.

### Running in a Claude Code cloud sandbox (gotchas)
- **Use the proxy:** outbound HTTPS goes through a proxy that injects the OpenAI key. Start the server with
  `NODE_USE_ENV_PROXY=1 OPENAI_API_KEY=sk-dummy BUNNY_PASSCODE=carrots AUTH_SECRET=test npm start`
  (`npm run build` first). Without `NODE_USE_ENV_PROXY=1`, Node's `fetch` bypasses the proxy and gets a 401.
- **No live calls:** WebRTC media (UDP) is blocked, so a live call can't connect in the sandbox. Test her voice and personality with `tools/voice-test.mts` instead (it uses WebSocket).
- **Slow rendering:** WebGL runs on SwiftShader (software). Fur renders slowly, so animation only advances a few frames per second. For gesture screenshots use `--hold`, `--wait 6000` and `--shells 3..6`.
- **The proxy rewrites the browser's auth header.** That's why `useBunnyCall` passes `?model=` on the `/v1/realtime/calls` URL. It's harmless in production.

## 4. Workflows

Always finish with: `npm run check:types`, `npm run build`, the relevant checks below, then commit and push (which deploys).

### A. Change her look (shape, colour, patches, stitches)
1. Edit `blender/build_oney.py`. Constants are near the top:
   - `COLORS`
   - face layout: `EYE_UV`, `MUZZLE_POLY`, `NOSE_POLY`, `MOUTH_TOP`
   - part shapes: `head_radius`, `body_radius`, `thigh`, `foot`, `ear_frame` / `ear_profile`, `arm_curve` / `arm_dims`
   - gesture-facing details: `PALM`, `paw_stitch_lines`
2. If you moved arms or ears: `.bvenv/bin/python tools/clearance.py`. Nothing should be negative; keep arms at least 0.015 and ears at least 0.012–0.02 clear.
3. `npm run model` (or `npm run model:renders` for Cycles previews; `npm run model -- --no-bake` skips the AO bake for a quicker shape check).
4. Start the server, then screenshot and compare with the photos:
   ```bash
   node tools/shots.cjs --out .oney-out/front
   node tools/shots.cjs --out .oney-out/face --view face          # also: side, paw
   python3 tools/sheet.py .oney-out/cmp.png reference/photos/front.jpg .oney-out/front.png
   python3 tools/sheet.py .oney-out/paw.png --crop 0.48,0.40,0.72,0.61 reference/photos/held-paw.jpg .oney-out/front.png
   ```
5. `npm run check:solid`: every pose must end at about 0 cm penetration.

### B. Add or tune a gesture or animation
1. **Motion** lives in `src/components/bunny/rig.ts` (`useBunnyAnimator`):
   - mode targets: idle, listening, thinking, talking
   - tricks: `bunnyState.trick`
   - held gestures: `bunnyState.gesture`, plus `GESTURE_SECONDS` in `src/lib/bunnyState.ts`
   (new gestures: add the pose to `TARGETS` in `tools/solve_poses.py`, to `Poses`/`DEFAULT_POSES` in `rig.ts`, and blend it in `arm()`)
2. **Per-model settings** live in `src/components/bunny/GlbBunny.tsx`: the lop-ear flags (`earXSign`, `earAmount`, `earSad`, `earMaxIn`) and the arm `poses`.
3. **Arm poses for the current arm shape:** `.bvenv/bin/python tools/solve_poses.py` (edit `TARGETS` for new gestures), then paste the output into `poses`.
4. **Expose it to her:** add it to the `express` tool enum in `src/lib/useBunnyCall.ts` and `tools/voice-test.mts`, and describe when to use it in `src/lib/prompt.ts`.
5. **Check it:**
   - `node tools/shots.cjs --out .oney-out/g --hold --shells 4 --wait 6000 --actions <name>`
   - `npm run check:solid -- --poses <name>`
   - try it live at `/preview?hold=1`

### C. Change personality, speech or memories
1. **Character sheet:** `src/bunny.config.ts` (`speech` rules, `examples`, `family`, `personality`, `world`, `memories` (TODO lines are skipped), `voiceStyle`, `voice`, `pitchSemitones`). The prompt is assembled in `src/lib/prompt.ts`.
2. **Test it:** start the server, then `npm run check:voice` (or `npx tsx tools/voice-test.mts --lines "...|..."`). Read every line: toddler voice? correct names? no narrated moves, no "let me…" preambles? sensible `express` and `remember_this` calls?
3. **Name or pronunciation changes:** `npx tsx tools/voice-test.mts --lines "What's your name?|Miffy, tell Booba your name!" --audio .oney-out/voice --transcribe` should be heard as "Wunny".

### D. Change her voice or pitch
- Audition voices at `/voices`. It has a pitch slider and plays through the same shifter.
- Measure: `npx tsx tools/voice-test.mts --audio .oney-out/v`, then `python3 tools/audio/f0.py .oney-out/v/*-phone.wav`. Aim for about 300–400 Hz median.
- Change `voice` and `pitchSemitones` in the config. **Vercel env `BUNNY_VOICE` and `BUNNY_PITCH` override them**, so update those too.

### E. Deploy
- Push to `main`, and Vercel builds it in about a minute.
- Vercel project `miffy`: team `team_9Y5GYcT795xBTZtFBSrcLrhz`, project `prj_mR0TngePPeFaF7CHzWNfsGouyBZX`.
- Env vars are set in the Vercel dashboard (or with the Vercel connector). The Vercel connector can read deployments and build logs.

### Call flow and voice: `src/lib/useBunnyCall.ts`
- **Session setup:** `/api/session` (`src/app/api/session/route.ts`) creates the ephemeral key (`POST /v1/realtime/client_secrets`) with semantic VAD, near-field noise reduction, and transcription with name hints. It returns `instructions`, `voice`, `model` and `pitchSemitones`.
- **Connecting:** `@openai/agents/realtime` (`RealtimeAgent` + `RealtimeSession`, WebRTC). Everything starts from the Call tap, because iOS needs a user gesture for the AudioContext unlock, the mic and the ringback.
- **Reply audio path:** reply track → `pitch-shifter` AudioWorklet → speakers, with an `AnalyserNode` tapped off to drive the talking animation. The `<audio>` element stays attached but muted, because Chrome needs it to deliver the remote stream.
- **Animation states:** server events (`speech_started` / `stopped`, `output_audio_buffer.*`) switch listening, thinking, talking and idle.
- **Picking up:** she waves automatically and speaks first, using a system message plus `response.create`.
- **Tools:**
  - `get_time_of_day`
  - `express` (wave, nuzzle, sad, hop, wiggle, spin, ear_flick, giggle, clap, cheer, shy, sleepy)
  - `remember_this`
- **Camera:** the camera button sends a small frame when Mommy starts speaking, at most one every 4 s.
- **Hanging up:** the transcript goes to `/api/memories` with keepalive. Facts are extracted and the transcript is discarded. No audio is ever stored.

### Memory: `src/lib/memories.ts`, `src/app/api/memories/route.ts`
Turso/libSQL. The table is auto-created (`db/schema.sql` is for reference). The newest 30 memories are injected into every call. View and edit them at `/memories`.

### Model loading and animation: `src/components/bunny/`
| File | Role |
| --- | --- |

**Animation states:**

| State | Motion |
| --- | --- |
| Idle | breathing, sway, random ear twitches |
| Listening | head tilts in, ears perk |
| Thinking | head tilts and looks up, one ear flops |
| Talking | voice-driven head bob, squish, jaw squash and ear bounce |
| Wave | left paw up beside her cheek |
| Sad | head bows, paws to her face |
| Nuzzle | leans in, rubs her head, arms forward |
| Tricks | hop, ear flick, wiggle, spin, giggle |
| Clap / Cheer / Shy / Sleepy | paws clap together / arms thrown up / bashful head-tilt with paws to cheeks / yawn and droop |
| Always on | organic breathing (quick inhale, slow exhale), independent ear sway, eyes that lead the head, blinks on gaze jumps, random idle fidgets (curious tilt, weight shuffle, shiver, stretch), a crouch before every hop, blinking (incl. double blinks), eye gaze, nose sniffs, tail wag, foot taps, floppy wrists, a `happy` level that squints eyes, wags the tail and kicks the feet |

**Skeleton contract (21 bones):**
- Bones: `root` → `body` → `chest` (spine; breathing, lean, head follow-through) → `head` → `jaw`, `nose` (sniffs), `eye_L`/`eye_R` (blink, squint, gaze: the eye patches are skinned to these), and three-segment ears `ear_{L,R}_1/2/3` (the tip flutters). `arm_{L,R}` (child of `chest`) → `paw_{L,R}` (floppy wrist, wave from the wrist). `foot_{L,R}` (kicks, taps) and `tail` (wag) hang off `body`. Aliases in `BONE_NAMES`. "L" is +x.
- Weights: `plush_weights` splits the body between `body`/`chest`/`foot_*`, and each arm between `arm_*` and `paw_*` (wrist at `PAW_T`). Ear weights come from `ear_w`.
- Collision samples: `arm_*` (upper arm), `paw_*` (t ≥ `PAW_T`+0.03) and `ear_*_1/2/3`; `collide.ts` resolves an arm with its paw spheres, then the paw alone.
- Every bone's local axes are **world-aligned** (in Blender each bone points straight up with roll 0), so rotations mean the same thing for both bunnies:
  - head: X nod, Y turn, Z tilt
  - arms and ears: X forward/back, Z out/in
- Gesture poses are absolute angles (`[rotX, rotZ, stretch]`); only the idle motion is scaled by `intensity`.

### The model build: `blender/build_oney.py`
- **Design space:** x right, y up, z toward the camera; she sits on y = 0 and is about 1.35 tall. It's converted to Blender's z-up and back by the exporter, so glTF coordinates equal design coordinates.
- **Plush body:** the head, body, thighs, feet and arms are signed-distance fields, `smin`-blended:
  - a soft neck (k = 0.07)
  - arms blended only at the shoulder (k fades with arm t)

  The result goes through marching cubes (voxel 5.5 mm) → decimate to about 44k tris → smooth.
- **Arms:** flattened ellipse-section tubes (`arm_dims`: broad face forward), widening into mitten paws. The cream underside panel is a vertex-colour region (`PALM`), and the finger stitches (`paw_stitch_lines`) are `thread_tan` with the fur shortened along them.
- **Patches** (muzzle, nose, eyes, mouth, tummy, soles, toe stitches): parametric appliqués **snapped onto the merged surface** (`on_plush`), so nothing pokes through when she moves.
- **Ears:** separate cupped ribbons that twist from the crown, with a lining and piping.
- **Skin weights:** a smooth field (`plush_weights`). An arm owns only points actually on the arm, so the face never follows an arm. Patches use the same field without arms.
- **Fur mask:** per-vertex `_furlen` (exported as `_FURLEN`), short or zero under patches, eyes, nose and stitch creases.
- **Colour:** `fur_tan` has a white base colour; its colour (tan, cream paw panels) times the baked AO lives in `COLOR_0`. The other materials use their base colour times AO.
- **Collision data:** SDF grids of the head (head-bone space) and body plus legs (body-bone space), and spheres along the arms and ears, each capped by its rest-pose clearance.

### Pitch shifter: `public/pitch-shifter.worklet.js`
A two-tap delay-line shifter: +4 semitones raises both pitch and formants (child-sized). `PitchShifterCore` is also `require()`-able in Node, which the voice-test tool uses.

## 6. Lessons learned (read before you repeat them)
- **Compare with the photos at the right resolution.** They're 1932×2576; use fractional crops (`tools/sheet.py --crop`).
- **Glossy renders are not the toy.** Judge the look with fur on (`tools/shots.cjs`), not only from Blender previews.
- **Vertex colours must be the active *and* render colour attribute** at export (the `export()` helper does this), or `COLOR_0` silently disappears and the body renders near-black.
- **React strict mode runs effects twice.** `applyFur` keeps the source material in `userData.furSource` and restores it on cleanup.
- **The first "arm into face" bug was skin weights, not geometry.** Arm weights must require proximity to the arm surface.
- **Long lop ears swinging inward cross her face.** `earMaxIn` clamps that. Ears are also pushed outward by arms (`collide.ts`).
- **Her name:** "Oney" and "Wunny" spellings were tried; "One-y" is the one the voice reliably says as WUN-ee (verified with cold transcription).
- **She narrates moves unless told not to.** Tool use must be silent, and the greeting must not say "good evening".
- **The software renderer is slow.** Gestures need `--hold` and long waits, or screenshots catch them half-blended.
